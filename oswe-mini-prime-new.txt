## API (required)

Use the programmatic API:

```python
from log_viewer import searcher
report = searcher.search(path="examples/sample.log", keyword="keyword", context=1)
# report is dict with 'results' and 'summary'
```

Report shape (per requirement):

- results: list of dicts with:
  - line_number (int), line (str), highlighted (str with `<<keyword>>` markers),
  - context_before (list[str]), context_after (list[str]), timestamp (str | None)
- summary: matches, total_lines, earliest_timestamp, latest_timestamp

Formatters are pure functions that accept the `report` dict and return a string:
- `log_viewer.formatters.text.format(report) -> str`
- `log_viewer.formatters.json_fmt.format(report) -> str`
- `log_viewer.formatters.pretty.format(report) -> str`

## 💡 Notes / Implementation details

- Matching semantics are preserved: simple substring match (case-sensitive), lines checked in file order, lines returned without trailing newline (same as original).
- Timestamps: the code tries ISO timestamps (e.g., 2025-12-24T10:00:00Z) and space-separated timestamps (e.g., 2025-12-24 10:02:00). Parsed timestamps are normalized to UTC-naive datetimes for consistent earliest/latest computation.
- Highlighting: the structured `report` stores `highlighted` as the line with `<<keyword>>` markers. The text formatter presents highlights as `**keyword**` and the pretty formatter renders colored ANSI output.
- Extensibility: adding more formatters is straightforward; they are pure functions taking the `report` dict.
